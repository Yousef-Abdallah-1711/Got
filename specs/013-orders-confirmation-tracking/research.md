# Phase 0 Research: Order Confirmation, Tracking, and Transactional Email

## Decision: Status-change email trigger

**Decision**: Hook into WooCommerce's native `woocommerce_order_status_changed` action, mapping specific transitions (→ Processing, → Out for Delivery via a custom status if needed, → Delivered via Completed, → Cancelled) to the project's 4 required email templates.
**Rationale**: Reuses WooCommerce's own reliable status-transition system rather than building a parallel one.
**Alternatives considered**: A custom status-tracking table updated manually alongside WooCommerce's own status (rejected — redundant, risk of the two falling out of sync).
**RESOLVED** (per `docs/adr/0016-order-status-mapping.md`, remediating cross-feature-analysis.md finding E1): "Out for Delivery" is registered as one new custom WooCommerce order status (`wc-out-for-delivery`) via the standard `wc_order_statuses` filter; "Delivered" maps directly to WooCommerce's native `Completed` status — no second new status needed. This is no longer an open question; `tasks.md` T003 implements this decision rather than researching it.

## Decision: Non-enumeration implementation

**Decision**: The tracking lookup queries for an order matching *both* order number and billing email in a single query; any non-match (wrong number, wrong email, or both) returns the exact same response object, generated by the same code path — not two different "not found" messages written separately (which risks accidental wording drift that becomes a de facto enumeration oracle).
**Rationale**: A single code path is the only way to *guarantee* FR-004 isn't violated by future edits (two similar-but-separately-maintained messages tend to drift).

## Decision: Rate limiting

**Decision**: Reuse the same hashed-IP, rolling-window rate-limiter built for early-access signup (Feature 005), applied to the tracking endpoint with its own (likely stricter) threshold.
**Rationale**: Avoids building a second rate-limiting implementation; the helper was explicitly designed to be reusable (Feature 005's research.md).
