# API Contract: Order Tracking Endpoint

## `POST /wp-json/got/v1/track-order`

**Request**: `{"order_number": "1007", "email": "karim@example.com"}`

**Responses**:
| Status | Body | Meaning |
|---|---|---|
| 200 | `{"found": true, "order_number": "1007", "status": "out_for_delivery", "timeline": [{"status": "processing", "at": "2026-10-09T10:00:00Z"}, {"status": "out_for_delivery", "at": "2026-10-10T08:00:00Z"}]}` | Exact match found |
| 200 | `{"found": false}` | **Used for every non-match case** — wrong order number, wrong email, both wrong, or order doesn't exist. Identical body and status code in all cases (FR-004). |
| 429 | `{"error": "Too many attempts. Try again later."}` | Rate limit exceeded |

**Authorization**: Public, rate-limited, no login required (this is explicitly the guest-tracking path; a logged-in customer's own order history, Feature 011, is a separate, authenticated view of the same underlying order data).

**Non-enumeration guarantee**: The `found: false` response is generated by one single code path regardless of *why* the lookup failed — enforced by not having more than one "not found" branch anywhere in the implementation.
