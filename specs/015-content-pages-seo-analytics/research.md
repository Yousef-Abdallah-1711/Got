# Phase 0 Research: Content Pages, SEO, and Consent-Gated Analytics

## Decision: Consent mechanism

**Decision**: A small custom consent banner (not a dedicated plugin), writing a `got_consent` cookie (`essential` | `all`) that gates whether the GTM container script tag is even inserted into the page at all.
**Rationale**: Per `docs/adr/0015-analytics-and-consent.md` — this requirement is contained enough to build directly, saving a plugin slot (PRD's 15-plugin cap) for something that needs a dedicated tool more.
**Alternatives considered**: A consent-management plugin (viable, not chosen — see ADR 0015 for full comparison).

## Decision: "Gated at the network level" enforcement

**Decision**: The GTM `<script>` tag itself is only written into the page's HTML when `got_consent === 'all'` — not written-but-disabled, not written-then-blocked by a client-side flag. If consent is rejected or unset, the tag literally does not exist in that page's HTML.
**Rationale**: This is the only way to make SC-001 ("zero non-essential analytics network requests") true at the network level rather than just at the application-policy level — a disabled-but-present script tag can still leak a request in edge cases (e.g., a race condition, a misconfigured trigger).

## Decision: SEO metadata approach

**Decision**: A minimal custom helper (`app/Support/Seo.php`) outputting canonical URL, JSON-LD (reusing Feature 008's product schema pattern for consistency), and Open Graph tags directly in the Blade layout — deferred decision on whether to also install a dedicated SEO plugin (Yoast/Rank Math, both named as options in PRD §9) for sitemap/robots generation specifically, since those are more tedious to hand-roll correctly.
**Rationale**: Avoids the documented risk of "duplicate schema generated by multiple plugins" (explicit project warning) by keeping one code path responsible for JSON-LD, even if a plugin is later added for sitemap/robots only.
**Alternatives considered**: A full SEO plugin for everything (viable, deferred to task-level choice, with the explicit caveat that if chosen, its own schema output must be disabled in favor of this feature's custom JSON-LD to avoid duplication).
