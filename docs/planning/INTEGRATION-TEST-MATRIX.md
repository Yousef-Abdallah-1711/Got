# Integration Test Matrix

Cross-feature end-to-end scenarios — each one exercises more than one feature's code in a single user journey, which is exactly what per-feature test suites (in each `specs/0XX/tasks.md`) cannot fully prove on their own. This matrix is the thing `docs/testing/commerce-test-matrix.md` (single-feature-scoped scenarios) feeds into at the integration level.

## Notes on execution

- Scenarios 1–9, 11–13, 15, 17 are suitable for the per-PR "smoke subset" of the CI pipeline described in `docs/testing/test-strategy.md`; scenarios 14 and 16 are heavier and run post-merge against staging only (visual regression and load testing are both explicitly placed in the "after merge, before phase-gate sign-off" stage in that document).
- Scenario 16 is new to this matrix — it did not exist in `docs/testing/commerce-test-matrix.md` because that document predates the load-test gap found during this audit's traceability pass.
- Every scenario above names the specific features whose *code* is exercised together, not just features that are thematically related — this is what makes it an integration test matrix rather than a restatement of each feature's own acceptance criteria.
