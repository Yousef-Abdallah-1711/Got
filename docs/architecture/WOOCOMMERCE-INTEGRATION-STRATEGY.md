# WooCommerce Integration Strategy

**Purpose**: One consolidated reference answering, for every commerce feature, which native WooCommerce capability is used, how it's extended, who owns the server-side code, what the browser does, and what the data source of truth is. This does not replace `docs/architecture/woocommerce-integration.md`, `CHECKOUT-AND-ORDER-LIFECYCLE.md`, or `PROMOTIONS-AND-PRICING.md` — it indexes them, so a reviewer can answer "how does GØT handle X" in one lookup instead of five.

## What this table is NOT

It is not a replacement for reading the actual feature specs — it is a navigation aid confirming, at a glance, that **no commerce feature in this project re-implements something WooCommerce already does natively**, and that the only two genuinely custom data concepts in the entire plan are Wishlist (justified — WooCommerce has no native concept) and the BOGO/early-access/order-tracking plugin logic (each individually justified in its own ADR). Avoiding unnecessary custom REST endpoints and duplicate business logic — the explicit goal of this document's commissioning request — is satisfied by construction: every row above either names a native WooCommerce mechanism directly, or names the specific, ADR-justified reason a small amount of custom code exists instead.
